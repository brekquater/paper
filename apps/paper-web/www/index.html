Word documents,
edited in the browser.

Paper is a document editor you embed in your web app. Open, edit and save DOCX files with a familiar ribbon, entirely on the user's device: no server, no uploads.

Paper's editor is built for a keyboard and a larger screen. It works here, but it is at its best on a desktop browser.

Loading the editor…

Private by design

Documents stay in the browser. Paper has no server, account or telemetry; your app decides where files go.

Real Word files

DOCX in and out, with styles, tables, lists, comments and tracked changes. Also .doc, ODT, RTF, HTML and Markdown, plus PDF export.

A ribbon users know

Pages laid out as they print, with the ribbon, rulers and dialogs people expect from a word processor.

Rust, in WebAssembly

One engine for the model, layout, formats and rendering, compiled to WebAssembly and drawn on a canvas.

A few lines to embed.

Give Paper a canvas, then drive it from your code: run commands, load and export documents, and listen for changes. Saves come to your app as events, never as downloads.

Component reference →

import init, { PaperEditor } from "./pkg/paper_web.js";

await init();
const editor = await PaperEditor.create(canvas);

editor.load("report.docx", bytes);   // open a document
editor.on("save", ({ name, bytes }) => store(name, bytes));
editor.execute("format.bold", "");   // any command, by id
const pdf = editor.export("pdf");    // Uint8Array
